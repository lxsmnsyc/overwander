- Read the brief, the contract stub, the three outline briefs, the `spawn-surfaces` and `world-generation` skills, `chunk-snapshot.ts`, `safari/index.ts`, `server/overworld/{spawns,claims}.ts`, `auth/snapshots.ts`, `board-view.ts`, `board/index.ts` and wAthena's `monster.go`.
- Finding: `spawnKey` is `chunkX,chunkY@window:individualValue`. It never held the cell. Only the window part is wrong for a slot clock, so the key is kept as is and the slot rides in the spawn id (`key@start#slot`). Raids, stops, gifts and `fled_encounters` stay untouched.
- Finding: the mythical, special and prized bands are inside every `pickSpawn` roll (1/4096, 1/4096, 1/512), not a channel. The contract moves them to a rare slot at 8 times the per-cycle odds to keep the hourly rate (about 96 rolls an hour today against about 11 cycles).
- Finding: spawns are drawn only inside `BOARD_RADIUS` (10.5 cells, 346 cells), not the 9 loaded chunks. The brief's 54 against 72 overstates the view. At a live fraction of 0.727, K = 6 gives 5.9 standing against 10.8 today.
- Finding: the server stages a meeting from `snapshot_spawns` (a stored copy of the window's rolls). A derived roll makes the table unnecessary and saves two selects per meeting. The client now sends the individual value it saw, so a tab on another build is refused rather than staged with a different roll.
- Design choices beyond the brief: no start jitter (rest is `330 s - present`, 1 to 2 min exactly). Cycles are cut at the local hour so one occupied set and one weather window cover a cycle. Start cells come from per-hour territories, one per slot, so slots never collide without reading each other. Roaming targets are independent per epoch inside a flood-filled area (path distance 4 from home, clipped to the chunk), so position needs no replay.
- Fingerprint test read: it digests terrain, scenery, landmarks, towns and the start for both generations and the cave. It never builds a `ChunkSnapshot`, so it pins no spawn. The design adds no `world.draws` call.
